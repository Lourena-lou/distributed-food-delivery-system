# Docker Deployment

The project provides two complete deployment variants. Run one at a time because
they intentionally expose the same service ports and API contracts:

- `compose.mongodb.yml`: seven Ballerina services, MongoDB 8.0, and Kafka;
- `compose.mysql.yml`: seven Ballerina services, MySQL 8.4, and Kafka.

Service images are generated by Ballerina Code-to-Cloud from each package's
`Cloud.toml`. Compose is responsible for configuration, networking, database
readiness, Kafka topic initialization, and persistent storage.

## Prerequisites

- Ballerina Swan Lake 2201.12.9
- Docker Desktop with the Linux container engine running
- Docker Compose v2

## Prepare configuration

From the `docker` directory:

```powershell
Copy-Item .env.example .env
```

Replace every example password in `.env`. The file is ignored by Git. These
credentials are suitable only for local development; use a secrets manager in
a deployed environment.

The Compose files provide each service's settings as Ballerina TOML through
`BAL_CONFIG_DATA`. This keeps the application settings and imported database
connector settings in one configuration source.

## Build all service images

```powershell
.\scripts\build-images.ps1
```

The script executes `bal build --cloud=docker` in every service package and
stops immediately if any image fails to build.

## Start one database variant

```powershell
.\scripts\start-stack.ps1 -Backend mongodb
# or
.\scripts\start-stack.ps1 -Backend mysql
```

MongoDB initialization creates a restricted application user, collection
validators, and indexes. MySQL initialization creates the normalized schema and
the official image grants the configured application user access to it. The
selected database and Kafka use named volumes, so normal shutdown preserves
their data.

## Verify and stop

```powershell
.\scripts\smoke-test.ps1
.\scripts\verify-kafka.ps1 -Backend mongodb
.\scripts\stop-stack.ps1 -Backend mongodb
```

Use `-Backend mysql` when that is the active variant. The smoke test waits for
all seven HTTP health resources and fails if any service remains unavailable.
The Kafka verification checks all eleven topics and their three partitions.

To intentionally reset a database, stop its stack and explicitly remove that
stack's named volume with Docker Compose. This destructive reset is not included
in the helper scripts.

## Published ports

| Component | Host port |
|---|---:|
| Customer Service | 9101 |
| Restaurant Service | 9102 |
| Order Service | 9103 |
| Payment Service | 9104 |
| Delivery Service | 9105 |
| Notification Service | 9106 |
| Admin Service | 9107 |
| MongoDB | 27017 |
| MySQL | `${MYSQL_PORT}` (`3306` by default) |
| Kafka | `${KAFKA_PORT}` (`9092` by default) |

If another local MySQL installation already uses port `3306`, set
`MYSQL_PORT=3307` (or another free host port) in `.env`. Services still connect
to MySQL on port `3306` inside the Docker network.
